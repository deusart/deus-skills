# Secrets

Секреты: где лежат, как попадают, как меняются.

## Правила

- `.env` в `.gitignore`, `.env.example` в репозитории и без значений
- у каждого секрета есть владелец и срок ротации
- секрет не печатается в лог, не попадает в ошибку, не уходит в трейс
- для SERVER отдельный `.env`, не копия DEV
- права на файл ограничены пользователем сервиса

## Если секрет утёк

1. Считать скомпрометированным, даже если коммит удалён из истории.
2. Перевыпустить, старый отозвать.
3. Проверить логи и историю git на предмет использования.
4. Записать инцидент в `docs/tasks`, чтобы был след.

## Что писать в docs

Список секретов: имя, где используется, владелец, как часто меняется. Без значений.

# Environments

DEV, SERVER и CI. Среда задаётся конфигом, а не копией кода.

## Шаблон для `docs/rules/environment.md`

| | DEV | SERVER | CI |
|---|---|---|---|
| Роль | проба и разработка | постоянная работа | проверка кода |
| Запуск | `compose.dev.yml` | `compose.server.yml` | `compose.ci.yml` |
| Данные | локальный volume | источник истины | синтетика |
| Секреты | локальный `.env` | `.env` на сервере | секреты пайплайна |
| Доступ | локальный | только LAN или VPN | нет |

## Правила

- код один, различия только в compose и `.env`
- данные не переезжают через git
- SERVER источник истины по данным и расписанию
- CI не ходит в боевые базы
- новый сервис появляется во всех трёх средах или обоснованно отсутствует

## Проверка паритета

Сравнить список образов и переменных между compose-файлами. Расхождение это ошибка,
если оно не записано в таблице выше.

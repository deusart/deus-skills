# Structure

Домен дерево. Артефакт в проекте: дерево в `README.md` плюс `docs/rules/structure.md`
с назначением каждой папки первого уровня.

## Базовая форма

```
project/
├── README.md
├── AGENTS.md
├── .gitignore
├── .deus-architect.yaml   # маркер проверки
├── tools/                 # проверки и обслуживание
├── skills/                # скиллы проекта
├── agents/                # скрипты и конфиги агентов
├── docs/                  # obsidian vault
└── src/                   # решение
```

## Лестница решений

Бери первый вариант, который полностью работает:

1. **Можно не создавать?** Новый файл, папка, инструмент оправдывается одной строкой.
   Нет оправдания, нет сущности.
2. **Уже есть в проекте?** Бери существующее. Второй способ делать то же самое не
   вводится.
3. **Стандарт платформы?** Бери, если проект его не переопределил.
4. **Уже установленный инструмент?** Используй. Новую зависимость вводишь, только если
   без неё решение не работает.
5. **Иначе:** минимальная своя конструкция, читаемая с первого взгляда.

## Правила

- одна папка = одна ответственность
- папка без назначения удаляется, две папки с одной ответственностью объединяются
- глубина внутри `src/` до трёх уровней; глубже это сигнал, что модуль не разделён
- скрипты в `tools/`, не в корне
- `docs/` внутри проекта, не рядом с ним
- сгенерированное не смешивается с рукописным

## Что писать в structure.md

Таблица: папка | назначение | что внутри | владелец. Одна строка на папку. Папка без
строки в таблице это ошибка проверки.

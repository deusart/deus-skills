# Agent environment

Домен среда агентов. Артефакты: `AGENTS.md`, `skills/`, `agents/`.

## AGENTS.md

Три блока, каждый короткой строкой и указателем:

1. **Как запускать:** команды сборки, тестов, проверок.
2. **Правила:** какие скиллы действуют, какие соглашения обязательны, что запрещено.
3. **Как проверять:** какая команда решает, что работа сделана.

Правило: AGENTS.md не дублирует содержимое других файлов, он указывает путь. Каждая
строка это либо команда, либо ссылка.

## Indirection

Путь к настройке живёт в одном месте. Остальные файлы и скиллы не хардкодят путь, они
говорят "правила должны были быть предоставлены". Поэтому структура такая:

```
AGENTS.md
├── docs/agents/issue-tracker.md   # где живут задачи
├── docs/agents/verification.md    # чем проверяется
└── docs/agents/domain.md          # где глоссарий и ADR
```

Перенос трекера или смена проверки правит один файл, а не десять.

## Скиллы проекта

```
skills/<name>/
├── SKILL.md          # name = имя папки, description = триггеры
├── references/*.md   # тяжёлое, читается по требованию
└── scripts/*.mjs     # исполняемое
```

- `description` описывает только когда звать, без пересказа процесса
- рядом лежит только то, что реально читается или запускается
- скилл без триггера не срабатывает, проверяется `tools/check-docs.mjs`

## Запрещено

- заглушки вида "будет дополнено позже"
- два скилла с одной ответственностью
- описание процесса в `description`
- скилл, который ссылается на путь, но не говорит, что путь настраиваемый
